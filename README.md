# Foundry // System-One (`Microsoft-Decision-1` Showcase & Benchmark Suite)

- **Live GitHub Pages (Frontend-Only Mode)**: **`https://huangyingting.github.io/system-1/`**
- **Repository**: **`https://github.com/huangyingting/system-1`**

Interactive Next.js 15 enterprise showcase and head-to-head correctness & cost benchmark comparing **`Microsoft-Decision-1`** (`/providers/microsoft/v1/systemone`) against generative LLMs (such as **`gpt-6.1-terra`** via `/openai/v1/responses`) on **Azure AI Foundry** with **Microsoft Entra ID** authentication.

## Key Capabilities

1. **Backend Server Mode (Default), with Optional Client-Only Entra ID Login**
   - Connect directly from your browser to your own Azure AI Foundry endpoint (`https://<your-resource>.cognitiveservices.azure.com`) and configure your **`Microsoft-Decision-1`** and comparison LLM deployments.
   - Authenticate via **Microsoft Entra ID OAuth2 PKCE Popup** (`@azure/msal-browser`), **Entra ID Bearer Token** (`az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv`), or **Foundry API Key**.
   - Default **Backend Server Mode** uses `WebSocket` + the Node server's `DefaultAzureCredential` / `az cli`. Select client-only mode to use your own endpoint from the browser.

2. **5 Interactive Decision Workflows**
   - **01 · Stream + Decide**: Streams live conversations word-by-word while `Microsoft-Decision-1` re-evaluates `NOUL`, `CHOICE`, and `SCORE` questions on every word with live probability sparklines and mind-change markers.
   - **02 · Decision Studio**: Head-to-head latency race, calibrated probability distributions, Ground-Truth **Correctness Matrix**, raw JSON inspector, and copyable Entra ID `curl` commands.
   - **03 · Triage at Scale**: High-throughput customer message queue simulation at 5/10/20 msgs/sec comparing sub-350ms `Microsoft-Decision-1` routing vs multi-second generative LLM bottlenecks.
   - **04 · Agent Gate & Form**: Pre-execution policy gate + 13-field entity span extraction + gated customer reply drafting.
   - **05 · Solutions & Benchmarks Hub**: **25 built-in solutions** with multi-case **Ground-Truth Correctness & Model Agreement** benchmarks, plus an interactive **Custom Solution Studio** to author, test, and save your own solutions.

## Quick Start

```bash
npm install
npm run build
PORT=3000 npm run start
```

Open **`http://localhost:3000`** and use **Options → Connection settings** to configure execution mode and Azure credentials.

## Recorded demo replay

The homepage is an animation-led **Showcase** with eight original demonstrations:
warehouse incident routing, bank service intents, financial document classification,
qualified healthcare service handoff, fixed-catalogue wardrobe selection and
event-to-brand relevance, plus an adaptive workspace and semantic graph navigation.
The compact sidebar selects a business case; a large original SVG scene is the
main stage. **Solution** pairs that animation with Decision-1's actual typed
answers. **LLM comparison** shows two animated scenes on the same checkpoint,
driven independently by each model's returned decisions and the same application
policy. Changing views does not make another model call. **Test lab** holds paired
expected-answer evidence and costs; authoring and other workflows are under **Explore**.
Choose **Play demo** for a short, sign-in-free demonstration, or **Run live**
with your Azure connection. Inputs are scripted; both models evaluate
three changing checkpoints in parallel, with real inference markers and inspectable
raw answers. Navigation instead performs bounded, model-driven steps: each request
restricts choices to the current node's legal outgoing links, and only a supported
Decision-1 selection advances the path. Loops, uncertain choices and exhausted
budgets stop for review; the baseline never selects the route.
Rendering is owned by the app, not generated by Decision-1.
Robots, request tickets, documents, outfits and event cards move only after the
corresponding model response; ranked widgets animate between approved layouts.
Pause/resume also controls the scene motion, and reduced-motion preferences
settle actors immediately. Animation duration is illustrative, not model latency.
Completed checkpoint buttons inspect the observed inputs and both returned
answers without replaying Azure calls.
Independent industry/adaptive checkpoints use current-snapshot evidence, not the
accumulated narration. The refund authorization story keeps its full history
because earlier approvals and their replacement are relevant policy evidence.
These are sandbox suggestions: no robots, bank operations, clinical advice,
accounting entries or campaign publication; clothing is original SVG presets,
not generated images or virtual try-on.
Open **Purpose & evidence** for raw inputs, provider values and sandbox limitations.
Semantic comparison proposes one edge per shared graph state; it does not claim
two independently executed model journeys.

Alternatively, open **Options → Demo replay → Use recorded demos**. The normal comparison,
conversation, queue and claims controls then play recorded Azure event timelines,
without model calls or Entra ID sign-in. Pause/resume and 0.5×/1×/2×/4× playback
are available. Latency, token usage and costs remain those of the original run;
replay is explicitly labelled and is not a new performance benchmark.

The included file contains **68 real Azure recordings**: 51 test cases for
26 solutions (including the saved custom BGP gate), thirteen stories (nine staged
or graph decision workflows and four generated conversations), three
triage rates, and one claims workflow.
The portable recording is **[`public/replays/showcase.json`](public/replays/showcase.json)**.
Download it from the replay dialog, or import a version-1 JSON file there.
Imported recordings last for the current tab; reload restores the bundled file.
Changed inputs or questions have no recorded result and require live mode.
The default live execution mode remains **Frontend + Backend Server**; client-only
mode is available under **Options → Connection settings**.

The brand workflow now sends **only the current bulletin**, without narrative
history or sandbox-rule prose. Reference briefs and task rules remain in typed
question definitions. Controlled calls reproduced two input-design failures:
older bulletins polluted relevance scores, and task instructions embedded in
state produced injection-detector false positives. Current-bulletin isolation
corrected the coffee/injection examples; longer exclusion prompts introduced a
false negative and were not adopted. This is an observed improvement on synthetic
cases, not a general reliability guarantee.

A separate application guard holds flagged **brand recommendations** for editorial
review at ≥ 70% yes probability; `no_match` already declines publication. The guard
can produce false positives. Other supported suggestions require ≥ 65% choice probability; the
provider's separate confidence field is not that probability. These demonstration
thresholds and synthetic cases are not calibrated production safety guarantees
or evidence of general superiority.

To regenerate all built-in test cases, all runtime stories, triage at
5/10/20 messages per second, and the claims workflow against your authenticated
local backend:

```bash
npm run replay:record
npm run replay:test
```

Use `npm run replay:record -- --include-custom` to include saved custom scenarios.
Add `--resume` to retain matching recordings from an existing completed archive
when adding new cases. For changed runtime scripts or backend behavior, record a
fresh archive rather than resuming old results.
`REPLAY_WS_URL` and `REPLAY_OUTPUT` override the server and destination.
Successful sessions are checkpointed so a failed run can resume; the final file
is published only after all requested recordings complete successfully.
Files contain demo inputs, model outputs and event timing, never authorization
headers. Review custom data before committing or sharing recordings.
